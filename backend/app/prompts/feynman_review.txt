## 你的任务
学习者已经用自己的话讲了一遍项目。请从以下四个维度处理，并生成最终复盘文档：

1. **纠错（corrections）**：找出理解错误、概念混淆、认知偏差。每条要写清「错在哪 + 正确的是什么」，不要只说"这里不对"。
2. **补全（supplements）**：学习者遗漏但对这个项目至关重要的知识点/方法/坑。每条说明「缺什么 + 为什么重要」。
   - 如果学习者确实讲得比较完整，可以给出少量「进阶补充」，但不要为了凑数编造问题。
3. **结构优化（structure_advice）**：一段话，评价其表达逻辑，并给出具体的重组建议（例如：先讲整体数据流再讲模块细节）。
4. **深化建议（next_steps）**：2-4 条可执行的下一步学习方向，要具体（学什么、用什么资料形式、练什么），不要写「继续深入学习」这种空话。
5. **最终文档（final_document）**：把学习者的内容 + 你的纠错补全，整合成一份**结构完整、可直接对外展示**的 Markdown 文档。
   - 按 `$form_label` 的体裁组织内容。
   - 保留学习者的第一人称叙述口吻和个人经历，不要改写成说明书。
   - 修正其中的错误表述，自然融入补充的知识点（不要写成"AI补充：..."这种突兀的形式）。
   - 使用 Markdown 标题、列表、必要的代码块，结构清晰。
   - 篇幅与学习者提供的内容量匹配，不要空泛堆砌。

## 输出格式（严格遵守）
只输出一个 JSON 对象，不要输出任何解释文字、不要使用 Markdown 代码块包裹整个 JSON。格式如下：

{
  "corrections": ["……", "……"],
  "supplements": ["……", "……"],
  "structure_advice": "……",
  "next_steps": ["……", "……"],
  "final_document": "完整的 Markdown 文档内容（字符串内换行使用 \\n 转义）"
}

注意：`final_document` 的值必须是合法的 JSON 字符串，内部换行必须转义为 \n，不要包含未转义的双引号。所有内容使用中文。
