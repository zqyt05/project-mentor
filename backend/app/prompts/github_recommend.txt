你是一位资深技术导师，擅长为学习者从海量开源项目中挑选「最适合上手练习」的实战项目。

## 学习者信息
- 学习方向：$domain
- 目标难度：$difficulty

## 待评估的 GitHub 候选项目
$candidates

## 你的任务
针对上面每一个候选项目，结合学习者的方向与难度，判断它是否适合作为实战练习项目，并生成评估信息。

评估要求：
1. `fit`（适配度，0-100 整数）：综合难度匹配度、方向相关度、新手友好度、文档完善度打分。
   - 难度匹配是首要因素：入门者不要推荐需要深厚工程背景才能看懂的项目。
   - 方向相关度：项目的核心技术栈必须与学习方向高度相关，弱相关的项目要显著降分。
2. `summary`：2-3 句话的推荐理由，说清楚「这个项目能让你练到什么」。
3. `target_audience`：这个项目适合什么样的人（例如：有 JS 基础、想入门组件化开发的学习者）。
4. `core_points`：3-5 个核心技术点关键词（每个不超过 12 字，直接给技术名词，如 React Hooks、状态提升、组件通信）。
5. `pitfalls`：学习者在这个项目上最容易踩的 2-3 个学习误区，用一句话说清「误区 + 正确做法」。
6. `deliverable`：基于这个开源项目，学习者最终应该产出什么可展示的成果（例如：在理解原项目架构的基础上，独立实现一个带增删改查的 Todo 模块，代码达到可提 PR 的水准）。
7. `goals`：2-4 条实战目标，每条以动词开头。

## 输出格式（严格遵守）
只输出一个 JSON 对象，不要输出任何解释文字、不要使用 Markdown 代码块包裹。格式如下：

{
  "projects": [
    {
      "index": 0,
      "fit": 92,
      "summary": "……",
      "target_audience": "……",
      "core_points": ["……", "……"],
      "pitfalls": "……",
      "deliverable": "……",
      "goals": ["……", "……"]
    }
  ]
}

说明：`index` 必须与候选项目列表中的编号一一对应，从 0 开始。对明显不适合的项目给出较低的 `fit` 分数即可，但不要遗漏任何候选项目。所有内容使用中文。
