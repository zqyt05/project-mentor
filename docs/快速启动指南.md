# ProjectMentor 快速启动指南

> 目标：从零到能用，约 5 分钟。
> 完整项目说明见 [README.md](../README.md)。

---

## 最省事的方式：用启动脚本

仓库内置了两个脚本，会自动处理 Python 虚拟环境、Node 版本探测、依赖安装与端口检查：

```bash
# 终端 1：启动后端
./scripts/start-backend.sh

# 终端 2：启动前端（会等待后端就绪提示）
./scripts/start-frontend.sh
```

然后浏览器打开 **<http://127.0.0.1:5173>**。

两个脚本都用 `Ctrl+C` 停止。下面的手动步骤是脚本的内部逻辑说明，便于你排查问题。

### ⚠️ 关于 Node.js

脚本会按以下顺序自动寻找 Node，**不需要手动配置**：

1. 系统 `PATH` 中的 `node`
2. DeepSeek Harness 自带的 Node（路径 `/Users/chloe/.dsh/.../node/bin/node`）

如果你的机器上两者都没有，脚本会提示你安装：

```bash
brew install node        # 推荐（你已装 Homebrew）
# 或到 https://nodejs.org 下载 LTS 版本
```

> **注意**：`pnpm` 不需要全局安装。脚本会用 `node` 直接执行 pnpm 的 JS 入口，
> 因此 `pnpm: command not found` 不影响使用。

## 手动启动（可选）

## 0. 前置检查

在开始前确认本机环境：

```bash
python3.11 --version    # 需要 3.11.x
node --version          # 需要 18+
pnpm --version          # 或使用 npm
```

如果 `python3.11` 不存在，推荐用 [uv](https://docs.astral.sh/uv/) 自动获取：

```bash
uv venv --python 3.11 backend/.venv
```

---

## 1. 获取 DeepSeek API Key（必填）

1. 打开 <https://platform.deepseek.com/api_keys>
2. 创建一个 API Key（形如 `sk-xxxxxxxx`）
3. 确认账户有可用余额

> 没有 Key 服务能启动，但所有 AI 接口都会返回
> `未配置 DEEPSEEK_API_KEY，请在 backend/.env 中填写后重启服务`。

## 2. 获取 GitHub Token（可选，建议）

1. 打开 <https://github.com/settings/tokens>
2. 生成 Personal Access Token，**不需要勾选任何权限**（只读公开仓库即可）
3. 不配置也能正常使用，只是 GitHub 搜索速率限制从 30 次/分降到 10 次/分

---

## 3. 配置环境变量

```bash
# 在项目根目录执行
cp .env.example backend/.env
```

编辑 `backend/.env`：

```dotenv
DEEPSEEK_API_KEY=sk-你的真实密钥
GITHUB_TOKEN=github_pat_你的令牌
```

> `backend/.env` 已被 `.gitignore` 忽略。**不要把真实密钥写进 `.env.example`。**

---

## 4. 启动后端

```bash
cd backend

# 创建并激活虚拟环境
python3.11 -m venv .venv
source .venv/bin/activate          # macOS / Linux
# .venv\Scripts\activate           # Windows

# 安装依赖
pip install -r requirements.txt

# 启动（--reload 便于开发时热重载）
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

首次启动会自动创建 `backend/projectmentor.db` 并建表。

**验证后端已就绪：**

```bash
curl http://127.0.0.1:8000/api/health
```

期望输出（`llm_configured` 应为 `true`）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "status": "ok",
    "app": "ProjectMentor API",
    "version": "1.0.0",
    "model": "deepseek-flash",
    "llm_configured": true,
    "github_configured": true
  }
}
```

---

## 5. 启动前端

**新开一个终端**（后端保持运行）：

```bash
cd frontend
pnpm install
pnpm dev
```

浏览器打开 <http://127.0.0.1:5173>。

> Vite 已把 `/api` 代理到 `http://127.0.0.1:8000`，无需额外配置跨域。

---

## 6. 走一遍完整流程

1. **输入学习方向**：例如 `React 前端入门`（技术类）或 `财务报表分析`（通用类），选择难度
2. **等待 20-40 秒**：技术类会检索 GitHub 并逐条评估适配度
3. **选择项目**：在项目卡片上点「开始学习」，AI 会拆解为 4-6 个阶段任务并计算 DDL
4. **执行任务**：在「任务列表」点「开始当前任务」，完成后点「标记完成」自动解锁下一个
5. **随时提问**：右侧答疑窗口会自动绑定当前任务的项目背景与交付标准
6. **完成全部任务**：进入「项目复盘」，用自己的话写一遍，AI 纠错补全并生成文档

---

## 7. 生产构建

```bash
cd frontend
pnpm build      # 产物：frontend/dist
pnpm preview    # 本地预览
```

## 故障排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 前端提示「无法连接后端服务」 | 后端未启动或端口不是 8000 | 确认后端运行在 `127.0.0.1:8000` |
| 提示「未配置 DEEPSEEK_API_KEY」 | `backend/.env` 缺失或未填 Key | 填好后**重启后端**（配置在启动时读取） |
| AI 回答为空字符串 | `deepseek-flash` 是推理模型，token 预算被思考过程耗尽 | 调大 `backend/.env` 的 `LLM_MAX_TOKENS`（如 16384）后重启 |
| 接口转圈很久 | 推理模型本身较慢：匹配 20-40s，复盘 30-90s | 正常现象，前端超时已设为 5 分钟 |
| GitHub 检索报 403 | 触发速率限制 | 配置 `GITHUB_TOKEN` |
| 技术类方向却给了定制项目 | 优质开源项目不足 3 个，按设计降级 | 预期行为，看返回的 `route_reason` 说明 |
| `pnpm build` 报 `ERR_DLOPEN_FAILED` | macOS Hardened Runtime 与 rollup 原生模块签名冲突 | 已通过 `frontend/pnpm-workspace.yaml` 的 rollup wasm override 规避；重新 `pnpm install` 即可 |
| 端口 8000 被占用 | 其他服务占用 | `--port 8001`，同时修改 `frontend/vite.config.ts` 的 proxy target |

```bash
# 停止后端，然后

# 重启后端会自动重建空表
```
