# ProjectMentor 开发版 PRD
> 说明：本文档为精准开发指令，明确MVP边界、技术栈、功能逻辑与交付标准，严格按范围实现，禁止自动扩展功能。

## 1. 项目基本信息
### 项目名称
ProjectMentor - PBL 项目制 AI 实战导师

### 项目定位
面向全领域学习者的通用AI实战学习工具，复刻企业导师带教逻辑，以「做项目」为核心学习方式，提供「项目匹配 → 任务拆解+DDL → 双窗口隔离答疑 → 费曼复盘输出」的完整学习闭环。
- 技术编程类领域：优先复用GitHub优质开源项目做实战
- 通用知识领域（金融、运营、职场、学科等）：AI自动生成定制化实战项目
- 核心价值：告别碎片化知识点学习，通过完成具体项目掌握可落地的能力

### 核心目标
1. 跑通完整MVP主链路，双窗口体验可用，流程顺畅
2. 代码结构清晰规范，适合开源到GitHub作为AI应用开发岗求职作品集
3. 兼顾技术特色与通用场景，产品定位完整，差异化明确

### 开源与简历导向要求
- 代码分层清晰，核心逻辑有注释，模块解耦
- 根目录包含规范README、快速启动指南、架构说明
- 敏感信息全部通过环境变量管理，禁止硬编码
- 遵循主流开发规范，便于后续迭代扩展

## 4. 核心功能模块详细需求
### 模块 1：项目智能匹配与生成
**功能描述**：用户输入任意学习方向，系统自动判断领域，选择最优路径生成实战项目选项。

**输入**：
- 学习方向/领域（文本输入，如「React前端入门」「财务报表分析」「新媒体运营」）
- 难度选择（下拉：入门 / 初级 / 中级）

**执行逻辑**：
1. **领域判断与路由**
   - 编程/开发/技术框架类方向 → 优先走「GitHub开源项目检索」路径
   - 非技术通用领域（金融、职场、运营、学科等） → 直接走「AI定制项目生成」路径
   - 技术领域但GitHub检索优质项目不足3个 → 自动降级到AI定制项目路径

2. **路径A：GitHub开源项目检索**
   - 调用GitHub Search API，筛选条件：stars > 500、近一年有更新、有完整README、语言匹配
   - 按stars倒序取Top10候选
   - 传入DeepSeek生成每个项目的：推荐理由、适配人群、核心技术点、练习侧重点、常见学习误区
   - 按难度匹配度排序，输出5个推荐项目

3. **路径B：AI定制实战项目生成**
   - 传入学习方向+难度，调用DeepSeek生成3个定制实战项目
   - 每个项目必须包含：项目名称、项目背景、实战目标、核心学习知识点、最终交付物、难度标签
   - **生成原则**：小而实、有明确交付物、强调实战性，而非知识点罗列。例如：
     - 学财务报表 → 生成「编制小型便利店月度资产负债表并做简要分析」
     - 学新媒体运营 → 生成「策划茶饮店新品上市小红书推广方案」
     - 学PPT → 生成「制作一份10页的互联网产品岗位求职简历PPT」
   - 项目颗粒度：可在1-2周内完成，适合拆解为4-6个阶段性任务

**输出**：项目卡片列表，每张卡片包含：
- 项目名称、项目来源标签（GitHub / 定制）、难度标签
- 项目简介/推荐理由（2-3句话）
- 核心学习点（3-5个关键词）
- 最终交付物说明
- GitHub项目额外展示：仓库地址、Star数、主要语言
- 「开始学习」按钮

**交互**：用户点击「开始学习」，系统初始化项目数据，进入项目学习总览页。

---

### 模块 2：项目拆解与DDL任务管理
**功能描述**：将选中的项目（无论GitHub还是定制）拆解为分阶段任务，设置DDL，明确交付标准与知识点。

**执行逻辑**：
1. 拉取项目完整信息（GitHub项目拉取README与目录结构；定制项目读取生成的详情）
2. 调用DeepSeek将项目拆解为4-6个学习阶段，每个阶段包含3-5个具体任务
3. 每个任务包含：任务名称、任务描述、需掌握知识点、交付标准、建议DDL天数
4. 设置关键里程碑（如：环境/准备完成、核心产出完成、整体交付完成、优化复盘）
5. 所有任务与阶段存入数据库，关联当前项目，两种项目来源复用同一套数据模型

**输出**：项目学习总览页（主任务窗口默认内容）
- 项目基本信息、学习目标、最终交付物
- 阶段化任务时间线（按顺序展示）
- 每个任务：状态（未开始/进行中/已完成）、DDL日期、知识点标签
- 整体进度条

**交互**：
- 用户可手动调整任务DDL日期
- 点击「开始当前任务」，任务状态变为进行中，右侧答疑窗口自动切换为该任务上下文
- 用户标记任务完成后，自动解锁下一阶段任务

---

### 模块 3：双窗口隔离式场景化答疑
**功能描述**：主任务窗口与答疑窗口物理隔离，任务记录永不被聊天冲刷；答疑自动绑定当前任务上下文，精准不跑偏。

**整体布局**：固定左右分栏
- **左侧：主任务窗口（约占70%宽度）**
  - 纯展示与任务操作区域，内容静态稳定
  - 展示：项目总览、任务列表、任务详情、复盘内容
  - 仅任务状态切换、页面切换会更新内容，不受聊天消息影响
- **右侧：独立答疑子窗口（约占30%宽度）**
  - 独立滚动的对话区域，仅用于提问与解答
  - 顶部显示当前绑定的任务名称
  - 底部输入框，支持发送问题

**联动规则**：
1. 用户在主窗口点击/切换不同任务，答疑窗口自动加载对应任务的：项目背景 + 任务信息 + 历史对话记录
2. 答疑窗口的所有对话、提问、刷新操作，**不影响主窗口的内容与状态**
3. 每个任务独立保存对话历史，切换任务时上下文自动隔离，互不干扰

**答疑执行逻辑**：
1. 每次提问自动拼接完整上下文：项目基本信息 + 当前阶段任务 + 技术栈/领域 + 该任务历史对话
2. Prompt要求DeepSeek：结合当前项目场景回答，优先给出实操指引，避免泛泛而谈；涉及操作步骤时分步说明
3. 回答支持Markdown格式、代码高亮、列表结构化展示

**交互**：
- 支持清空当前任务的对话
- 支持快速提问模板（如「这一步怎么做？」「我遇到报错了」）

---

### 模块 4：费曼学习法复盘输出
**功能描述**：所有任务完成后，引导用户用费曼学习法输出项目总结，AI进行纠错补全，完成知识闭环。

**触发条件**：用户标记全部任务完成后，主窗口自动进入复盘环节。

**执行逻辑**：
1. 提供3种复盘形式选项：结构化技术总结文档、项目复盘博客、面试口述提纲
2. 给出引导性问题，帮助用户输出：
   - 用通俗的话讲清楚这个项目是做什么的、整体逻辑是什么
   - 项目中最难的部分是什么？你是怎么攻克的？
   - 完成过程中踩过哪些坑？有什么经验教训？
   - 这个项目用到了哪些核心知识/方法？分别解决了什么问题？
3. 用户提交自己的复盘内容后，DeepSeek从以下维度处理：
   - 纠正理解错误与认知偏差
   - 补充遗漏的关键知识点
   - 优化逻辑结构与表达
   - 给出进一步深化学习的建议
4. 生成最终复盘文档，支持一键复制

**输出**：
- 左侧主窗口：复盘引导区 + 用户编辑输入区 + AI优化后的最终文档
- 右侧答疑窗口可继续就复盘内容提问

---

### 模块 5：全局导航与状态管理
**功能描述**：统一页面框架，支持功能切换，保证双窗口布局全局一致。

**页面结构**：
- 顶部导航栏：项目名称、整体进度条
- 主体区域：左右双窗口布局（全局保持）
- 左侧主窗口内置侧边菜单：项目总览 / 任务列表 / 项目复盘
- 右侧答疑窗口全局常驻，随主窗口内容自动切换上下文

**数据持久化**：
- 所有项目、任务、对话、复盘数据存入本地SQLite
- 支持查看历史学习项目列表

## 5. 完整用户操作主流程
```
用户输入学习方向 + 选择难度
    ↓
系统判断领域类型
    ├─ 技术类 → 调用GitHub API检索项目 → AI生成推荐理由
    └─ 通用类 / 检索不足 → AI生成定制实战项目
    ↓
展示项目列表 → 用户选择项目
    ↓
AI拆解项目为阶段任务 + DDL → 生成任务总览（左窗口）
    ↓
用户按顺序执行任务 → 右窗口随时提问
    ↓
（AI基于项目+任务上下文精准答疑，对话不影响左窗口）
    ↓
全部任务完成 → 进入费曼复盘环节
    ↓
用户输出复盘内容 → AI纠错补全 → 生成最终文档
    ↓
学习闭环完成
```
