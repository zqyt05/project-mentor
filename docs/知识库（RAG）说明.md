# 项目知识库（RAG）

把课程讲义、行业报告、自己的笔记上传到项目里，右侧答疑窗口回答前会先检索这些资料，
并在回答中标注引用了哪一份 —— 让回答从「凭印象」变成「有据可查」。

---

## 一、用起来是什么样

1. 进入项目 → 左侧菜单「**项目资料**」
2. 上传文件（`txt` / `md` / `pdf` / `docx`，单个 ≤ 5 MB）
3. 上传后立刻解析、分块、向量化，列表会显示「N 字 · M 个片段」
4. 回到「任务列表」，在右侧答疑窗口正常提问
5. 回答下方会出现「**本次回答依据了 N 份资料**」，列出文件名与相关度

页面里还有「**检索预览**」：输入一个问题，直接看到会检索到哪些片段（**不调用 AI、不花钱**）。
RAG 出问题时可用来快速区分是「没检索到」还是「检索到了但模型没用」。

---

## 二、技术选型与原因

### 为什么不用 DeepSeek 做向量化

DeepSeek 只提供对话模型（`deepseek-flash` / `deepseek-v4-pro`），
**没有 embedding 接口** —— 实测 `POST /v1/embeddings` 返回 404。

### 为什么用 fastembed 而不是 sentence-transformers

| | fastembed | sentence-transformers |
| --- | --- | --- |
| 底层 | ONNX Runtime | PyTorch |
| 依赖体积 | 几十 MB | 约 2 GB |
| 适合场景 | 本地轻量工具 | 训练/研究 |

对一个单用户本地工具，为了跑一个 512 维的中文向量模型装 2 GB 的 PyTorch 不划算。

### 模型选择

`BAAI/bge-small-zh-v1.5`，512 维，约 91 MB。

实测语义区分能力（问句「存货周转天数怎么算」）：

| 对比文本 | 相似度 |
| --- | --- |
| 存货周转率 / 周转天数（同主题） | 0.754 |
| React 的 useEffect 依赖数组（无关） | 0.328 |

### 为什么需要国内镜像

HuggingFace 直连在国内经常超时。代码默认把 `HF_ENDPOINT` 指向
`https://hf-mirror.com`；如有代理可自行设置环境变量覆盖。

### 为什么不用向量数据库

当前规模是「单用户、几个项目、几十份资料、几百个片段」，
暴力余弦检索完全够快。引入 Chroma/Milvus 只会增加部署复杂度。
向量存在 `knowledge_chunks.embedding`（JSON 列）里，接口设计成可替换，
将来量大时换存储即可。

## 三、降级策略（重要）

向量模型可能因为**网络、磁盘、平台兼容性**而加载失败。
此时**不会**让知识库整体不可用，而是自动退化为关键词检索：

- 功能照常工作，只是语义召回变弱（字面匹配 vs 意思匹配）
- 资料列表会标注「关键词检索」标签
- 页面顶部会明确提示「当前为关键词检索」及原因

这是刻意的设计：一个依赖网络的能力，不该在网络不通时让整个功能瘫痪。

**关键词检索的原理**：中文不加分词器，用字符二元组做重叠度打分，并过滤常见虚词
（的、了、和、是……）。代价是无法处理同义改写，好处是零依赖、永远可用。

## 四、检索的工程细节

### 分块

- 块大小 400 字，块间重叠 60 字
- 先按段落切，再贪心合并；超长段落内部强制切开
- 重叠是为了避免答案正好落在切点上被割断

### 相关度阈值

向量检索低于 **0.35**、关键词检索低于 **0.15** 的片段会被丢弃，
**不硬塞进上下文**。塞进无关内容只会干扰回答 ——
实测「今天天气如何」在财务资料库上返回 0 条，这是期望行为。

### 标注出处

注入提示词时给每段编号（`[资料1]`、`[资料2]`），并要求模型引用时标注编号。
实测回答会写成「依据你上传的笔记 [资料1]」。

### 不消耗每日 AI 配额

向量化是**本地模型推理**，不产生 API 费用。每日配额（`DAILY_LLM_CALL_LIMIT`）
只约束会花钱的对话模型调用。上传资料不受配额限制。

## 五、数据与迁移

两张新表：

| 表 | 作用 |
| --- | --- |
| `knowledge_documents` | 一份上传的文件（用于列表与整体删除） |
| `knowledge_chunks` | 切分后的片段 + 向量（检索的最小单位） |

它们是**新增表**，`create_all` 会自动创建，**不需要删库**，原有数据不受影响。

删除资料时片段由 ORM 级联删除（刻意不依赖数据库的 `ON DELETE CASCADE`，
因为 SQLite 默认不启用外键约束，依赖它会让生产与测试行为不一致）。

## 六、常见问题

**Q：上传后提示「向量模型未就绪」**
首次使用需要下载约 91 MB 模型。确认能访问 `hf-mirror.com` 后重启后端，
会自动下载。期间功能以关键词检索运行，不影响使用。

**Q：扫描版 PDF 上传后提示「没能提取到文字」**
PDF 是纯图片，需要先做 OCR。本项目只做文本层提取。

**Q：为什么检索不到我明明写过的东西**
大概率是问法与原文差异太大。两个办法：换更接近原文的说法，
或看「检索预览」确认实际召回的内容。

**Q：能不能检索历史答疑和复盘**
当前版本只接入了「上传资料」这一个来源。表结构（`source_type` 可扩展）
留了余地，后续可以把历史对话也灌进同一个知识库。

**Q：模型可以换吗**
可以，但**换模型会让已有向量失效**（维度/语义空间不同），需要清空
`knowledge_chunks` 并重新上传资料。
