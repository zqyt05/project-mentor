# 演示部署指南

把 ProjectMentor 通过公网分享给朋友小范围试用的完整步骤。

---

## 一、先明确三件事

### 1. 这是一个「共享你本机」的方案

```
朋友的浏览器 ──HTTPS──> Cloudflare ──隧道──> 你的 Mac:8000 ──> SQLite + DeepSeek
```

**你的电脑就是服务器**：关机、休眠、合盖都会让链接失效。关闭隧道终端即断开公网访问。

### 2. 为什么不用 Vercel / Netlify / Render

本项目有三个 LLM 长请求接口，实测耗时：

| 接口 | 实测耗时 |
| --- | --- |
| `POST /api/project/match` | 13–43s |
| `POST /api/project/start` | **约 51s**（任务拆解要输出约 14 个任务的 JSON） |
| `POST /api/review/generate` | 约 36s |
| `POST /api/chat/ask` | 15–23s |

对照各平台的请求超时：

| 平台 | 超时 | 能否跑通 |
| --- | --- | --- |
| Vercel Hobby / Pro | 10s / 60s | ❌ `start` 必挂 |
| Netlify Functions | 10s / 26s | ❌ 必挂 |
| Render 免费层 | 硬超时 + 15 分钟休眠 | ⚠️ 大概率挂 |
| **Cloudflare 隧道** | 100s | ✅ |

Cloudflare 隧道是普通 TCP 代理，不施加 Serverless 的函数级超时，是唯一零成本且能跑通的方案。

### 3. 你的 API Key 会为所有访客付费 ⚠️

**必做**：登录 [DeepSeek 控制台](https://platform.deepseek.com/) 设置**消费上限**。
这是防止链接外泄后被陌生人烧掉额度的最后一道防线，不是可选项。

---

## 二、启动步骤

### 第 0 步：设置消费上限

见上。**先做这一步。**

### 第 1 步：构建前端

演示模式下由后端托管前端产物（前后端同源，免 CORS）：

```bash
cd frontend
pnpm build
```

### 第 2 步：设置演示口令

编辑 `backend/.env`，加入：

```env
# 演示口令：填空则关闭门禁（本地单用户模式）
DEMO_PASSWORD=你自定义的口令
```

口令同时用作访客身份 Cookie 的 HMAC 签名密钥。
**更换口令会让所有已登录的访客失效**（需重新输入），但他们的数据仍在。

### 第 3 步：启动演示服务

```bash
DEMO_PASSWORD='你自定义的口令' ./scripts/serve-demo.sh
```

启动后会看到：

```
🔐 演示门禁：已开启（访客数据互相隔离）
🚀 启动演示服务：http://0.0.0.0:8000
```

先在本机打开 <http://127.0.0.1:8000> 确认能正常访问并输入口令。

> 注意：这一步用的是**生产模式**（无 `--reload`、同源托管），
> 与日常开发的 `start-backend.sh` + `start-frontend.sh` 是两套。

### 第 4 步：安装并启动隧道

```bash
brew install cloudflared          # 只需一次
./scripts/share-tunnel.sh          # 另开一个终端
```

终端会输出一个地址：

```
https://xxxx-xxxx.trycloudflare.com
```

### 第 5 步：把链接和口令分开发给朋友

**建议分两条消息发**（降低一起被转发的风险）：

> ① 这是我做的学习工具，麻烦帮我试试：https://xxxx.trycloudflare.com
> ② 口令是：xxxxxx

## 三、访客隔离是怎么工作的

### 数据隔离

- 朋友输入口令后，后端签发一个**签名 Cookie**（`pm_visitor`），内容是随机访客 ID
- 每个项目落库时记录 `owner_id = 访客 ID`
- 所有项目级/任务级接口都会校验归属，不符返回 **404**（不是 403 —— 403 会暴露「这个 id 存在」）

实测验证：访客 B 无法读取、修改或删除访客 A 的任何数据，
包括通过 `project_id`、`task_id` 猜测 id 的越权尝试。

### 明确不解决的问题

| 问题 | 影响 | 缓解 |
| --- | --- | --- |
| 清除浏览器 Cookie / 换设备 | 失去自己的项目列表 | 项目仍在库中，但访客 ID 丢失后无法再关联 |
| 口令泄露 | 任何人都能进入 | 但**看不到**既有访客的数据（各自身份独立） |
| 无速率限制 | 单个访客可以反复触发 LLM | 依赖 DeepSeek 消费上限 |
| 无 HTTPS 强制 | 本地 http 调试时 Cookie 不带 Secure | 隧道本身是 HTTPS |

**想彻底解决这些，需要完整的账号体系**，那超出「小范围试用」的范围。

## 四、试用期结束后清理数据

所有访客共用一份 SQLite。试用结束后删掉测试数据：

```bash
# 停服务后再删（进程持有句柄时删除会导致写入失败）
# 只删访客数据，保留 owner_id 为空的本机数据：
sqlite3 backend/projectmentor.db "DELETE FROM projects WHERE owner_id IS NOT NULL;"
```

> 注意：项目删除会级联清理任务、对话与复盘（外键 `ON DELETE CASCADE` + `PRAGMA foreign_keys=ON`）。

## 五、常见问题

**Q：打开链接是 `{"code":404,"message":"Not Found","data":null}`**
隧道通了，但 8000 端口上跑的是**开发模式**后端（`start-backend.sh`）。

区别在于 `SERVE_FRONTEND`：

| 脚本 | 静态托管 | 用途 |
| --- | --- | --- |
| `start-backend.sh` | ❌ 关闭 | 日常开发（配合 5173 的 Vite） |
| `serve-demo.sh` | ✅ 开启 | 对外演示（同源托管前端） |

隧道代理的是**端口**而不是某个进程，所以哪个后端占着 8000，公网看到的就是哪个。
分享期间必须用 `serve-demo.sh`，此时不能同时跑 `start-backend.sh`（端口冲突）。

判断方法：看后端启动日志有没有 `前端静态托管已开启` 这一行。

**Q：朋友打开链接显示「无法连接」**
你的电脑休眠了，或隧道终端被关掉了。保持两个终端都开着，并在系统设置里关闭自动休眠。

**Q：朋友卡在匹配很久最后超时**
先看后端终端日志。GitHub 检索偶发网络失败会报错；重新点一次通常就好。
真实耗时 1–2 分钟属正常（含 2 次 LLM 调用）。

**Q：想换口令**
改 `backend/.env` 的 `DEMO_PASSWORD` 并重启服务。所有访客需重新验证，
但各自的数据都还在（访客 ID 存在 Cookie 里，不受口令影响）。

**Q：想临时关掉门禁**
清空 `DEMO_PASSWORD` 并重启。此时所有人共用一份数据，且无需口令。

**Q：想要固定域名、不想让电脑一直开着**
需要改用常驻云主机（Fly.io 等）。因为存在 51 秒的长请求，
必须选支持长连接的平台并挂载持久卷存放 SQLite；
同时要把 `SERVE_FRONTEND` 与 `DEMO_PASSWORD` 配置为环境变量。

**Q：数据库结构升级了怎么办**
当前使用 SQLAlchemy `create_all`，**不会**给已有表加列。
模型变更后需要删除 `backend/projectmentor.db` 重建（会丢数据）。
有真实用户数据后应当引入 Alembic 迁移。
